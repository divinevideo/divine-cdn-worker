## Project Notes

## Blossom SDK Worker Architecture Analysis

### Current Content Serving
- Main entry: `/src/index.mjs` (2047 lines)
- Content served via `GET /{sha256}` endpoint
- Supports range requests for streaming
- Has moderation integration checking `MODERATION_KV` with tiered access control

### Storage Architecture
- **R2 Storage**: `src/storage/r2-blob-storage.mjs` - stores blobs at `blobs/{sha256}` path
- **KV Metadata**: `src/storage/kv-metadata-store.mjs` - stores metadata at `blob:{sha256}` keys
- Legacy paths: `videos/{sha256}.mp4`, `{sha256}.mp4`, `uploads/` for ArchiveTeam Vine files

### Existing Deletion
- DELETE endpoint exists at line 214-220 in index.mjs
- `handleDeleteBlob()` function (lines 715-740)
- HARD delete: removes from R2 + KV + owner relationships
- Requires Nostr auth + ownership check
- Uses `removeBlob()` on both storage backends

### Moderation System
- **MODERATION_KV namespace** - shared with divine-moderation-service
- Tiered access control (lines 235-316):
  - `permanent-ban:{sha256}` - returns HTTP 451, never serves
  - `age-restricted:{sha256}` - requires Nostr auth + NIP-78 preferences
  - REVIEW - serves normally, logged for review
  - SAFE - serves without restrictions
- Uploads queued to MODERATION_QUEUE (line 633+)

### BunnyStream Integration
- **BunnyStreamClient** (`src/streaming/bunny-client.mjs`):
  - createVideo(), getVideo(), deleteVideo(), uploadFromUrl()
  - listVideos() for pagination
- **Upload Strategy** (`src/streaming/upload-strategy.mjs`):
  - Routes videos to R2/Bunny based on BUNNY_UPLOAD_DEST config
  - Hash-based distribution for gradual rollout
- **Webhook Handler** (`src/streaming/bunny-webhook.mjs`) - processes encoding events
- **D1 Database** - logs webhook events, tracks video processing status

### Database Schema (schema-d1.sql)
- `bunny_webhook_events` - logs Bunny processing events
- `video_metadata` - links SHA256 to Bunny videoId, current status, URLs
- NO deleted/hidden flags currently exist

### KV Storage Keys
- `blob:{sha256}` - blob metadata (size, type, uploaded timestamp)
- `owner:{sha256}:{pubkey}` - ownership relationship
- `pubkey:{pubkey}:{sha256}` - reverse index
- `bunny:video:{videoId}` - Bunny video metadata
- `permanent-ban:{sha256}` - permanent ban flag
- `age-restricted:{sha256}` - age restriction metadata

### Key Gaps for Content Deletion
1. No soft delete mechanism - only hard delete exists
2. No "deleted" flag in KV or D1 schemas
3. No tracking of who deleted content or when
4. BunnyStream deletion not integrated with blob deletion
5. No relay request authorization for deletions
6. No audit trail for deletions
