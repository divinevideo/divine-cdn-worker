## Project Notes

**Cache Implementation - Review and Fixes:**

**Original Implementation Issues:**
1. Cache key included headers → would fragment cache massively
2. Duplicate duration checks in HLS + PlaybackResolver
3. R2 caching in legacy handler instead of edge cache
4. OPTIONS responses not cached (unnecessary CORS preflight latency)

**Fixes Applied:**
- Cache key now URL-only (prevents fragmentation)
- Removed HLS endpoint duration check (trust PlaybackResolver)
- Simplified legacy UID handler (removed R2 caching)
- Added OPTIONS caching (CORS preflight now 1-5ms instead of 50-200ms)
- Improved logging (full pathnames instead of truncated)

**Expected Performance After Fixes:**
- Cache hit rate: >90% (was going to be ~30%)
- Cache hits: 1-5ms (no Worker execution)
- Cache misses: 50-200ms (full KV + R2)
- OPTIONS preflight: 1-5ms cached (was 50-200ms every time)

**Testing Checklist:**
```bash
# Verify cache hit rate
curl -I https://cdn.divine.video/{sha256}  # MISS
curl -I https://cdn.divine.video/{sha256}  # HIT

# Verify no header fragmentation
curl -H "User-Agent: A" https://cdn.divine.video/{sha256}  # MISS
curl -H "User-Agent: B" https://cdn.divine.video/{sha256}  # HIT (same cache!)

# Verify OPTIONS caching
curl -X OPTIONS https://cdn.divine.video/{sha256}  # MISS
curl -X OPTIONS https://cdn.divine.video/{sha256}  # HIT
```
